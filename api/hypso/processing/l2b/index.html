hypso.processing.l2b#

L2A to L2B: geophysical products in their own files.

An L2B product holds products derived from one L2A product, one group per file (hypso.io.naming.L2B_GROUPS), as PACE OCI’s suites: BGC holds chlorophyll-a and suspended matter, IOP absorption, scattering, backscattering and Kd. Like PACE’s OC_AOP suite, the L2A keeps Rrs and the AC tool’s aerosol optical depth. An L2B file has 2D variables only, no band cube; per-wavelength quantities are separate variables (aph_443, bbp_443), as in NASA’s OC_IOP files. It keeps the L2A’s geometry, pixel_flags, grid and metadata, so it can be regridded, windowed and read by Satpy like any other level. File names: ...L2B.<GROUP>.<source>.nc, where the source is the algorithm (e.g. oc4) or the AC tool whose own product it is (e.g. polymer). An OC-SMART run thus writes L2A.RRS (Rrs, aod), L2B.BGC, L2B.IOP and L2A.AUX.

The AC tool’s other per-band outputs (OC-SMART’s Lt, Lr, Lrc, Lwp, tg_sol, tg_sen, …) go to another file next to the L2A, ...L2A.AUX.<method>.nc (split_intermediates()), built the same way: 2D variables only, one per quantity and band (Lt_434), with the L2A’s geometry and flags.

An L2B tree from an L2A tree and the derived variables.

Parameters:

  • tree (xarray.DataTree) – The L2A product the variables were derived from.

  • group (str) – Product group, a key of hypso.io.naming.L2B_GROUPS.

  • source (str) – Algorithm or tool, e.g. "oc4" or "polymer" (a file-name token).

  • variables (dict) – {name: xarray.DataArray or (array, attrs)}, each of the product’s spatial shape; attributes should include units and long_name.

Separate an L2A’s AC-tool products from its reflectance.

Parameters:

tree (xarray.DataTree) – An L2A tree, e.g. from hypso.processing.correct_atmosphere() or an L2A file written before the products moved to L2B.
