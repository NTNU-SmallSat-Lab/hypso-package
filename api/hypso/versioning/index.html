hypso.versioning#

Version and source identity of hypso and the hypsoN_calibration packages, for product provenance (hypso.io.provenance).

All three packages share one version, derived from git tags (vYY.M.N) by setuptools_scm at build time - see docs/versioning.rst. At runtime the version a product records must describe the code that actually ran, which the build-time version does not always do:

  • An editable install (pip install -e) writes _version.py once, at install time; later commits don’t change it. So when a package’s own directory is inside a git work tree, git is asked directly.

  • importlib.metadata reports whatever distribution of that name is installed, which is not necessarily the copy being imported (e.g. a refactor checkout on sys.path while production’s hypso2_calibration 26.5.1 is installed in the same env). Metadata is only trusted when its files include the imported module.

Lookup order: git -> _version.py next to the module -> matching installed metadata -> “0.0.0+unknown”.
