hypso.io.product#

One reader and one writer for every HYPSO product level, on xarray.DataTree.

In-memory model (what read_product() returns and write_product() takes):

/                     root Dataset
    <prefix>          product cube, dims (lines, samples, bands), or
                      (y, x, bands) on a map grid (hypso.grid): "dn"
                      (L1A), "Lt" (L1B/L1C), "rhot" (L1D), or the AC
                      variable for L2A (e.g. "Rrs", "rhos")
    wavelength        coord (bands): nominal band centre, 0.1 nm rounded
    radiation_wavelength  coord (bands): precise as-calibrated centre
    fwhm              coord (bands)
    latitude, longitude, crs_wgs84, <angles>   only when georeferenced
    pixel_flags       optional CF flag variable (hypso.masks.flags);
                      the product itself is unmasked
    <other>           any other 2D variable - derived products such as
                      a chlorophyll map - with its attributes
    x, y, crs         gridded products only: projection coordinates and
                      the CF grid-mapping variable (latitude/longitude
                      stay, as 2D auxiliary coordinates)
    attrs             global attributes; processing_level is required
/metadata/<group>     one child node per metadata group

On disk the cube is one 2D variable per band (Lt_378, …), the layout ESA SNAP reads, with geometry at the root and metadata/* nested. All CF attributes come from hypso.io.cf, so a file read in any supported layout is written back in the current one. Supported layouts: current flat files, older grouped files (/products and /geometry), and ground-station L1A files (one uint16 /products/dn cube).

hypso.io.product.write_netcdf_safely(tree, path, encoding=None, retries=1)[source]#

Write a DataTree to NetCDF so that path is either the complete file or untouched.

The file is written on local disk first ($HYPSO_WRITE_TMPDIR, default the system temporary directory), copied next to the destination as <name>.part, checked (SHA-256 of the copy against the local file) and renamed into place. An HDF or I/O error retries the whole write retries times. Writing NetCDF/HDF5 directly to a network file system failed now and then (“NetCDF: HDF error” in about 1 of 100 writes to the NFS home, 2026-11); a plain sequential copy is far less exposed, and a failed attempt never leaves a partial file under the real name.

Parameters:

  • tree (xarray.DataTree)

  • retries (int)

Return type:

pathlib.Path

hypso.io.product.write_product(tree, path, datacube=False, significant_bits=SIGNIFICANT_BITS)[source]#

Write a product tree in the current file format.

Parameters:

  • tree (xarray.DataTree) – In-memory model (see the module description).

  • path (str or pathlib.Path)

  • datacube (bool, default False) – Write the cube as one 3D variable instead of one variable per band.

  • significant_bits (int or None, default 14) – Keep this many significant mantissa bits of the float band variables (L1B-L2A; netCDF BitRound, max relative error 2**-(bits + 1); values stay float32, NaN is kept, readers need nothing special). None writes them lossless. L1A counts, geometry, derived variables and metadata are always lossless. Recorded in the band_quantization global attribute.

Return type:

None
